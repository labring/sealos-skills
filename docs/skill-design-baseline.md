## Observable Baseline Trace Contract

The machine fixture in `tests/fixtures/skill-design-baseline.json` records one positive and one violating case per physical owner. Every case carries these D-12 fields:

- **selected owner** — the canonical skill name selected by the broad or direct route.
- **loaded resource** — one-level owned module/reference paths and source entry paths loaded for the branch.
- **tool call** — deterministic helper or command invocation names; provider calls are represented as offline descriptions.
- **files** — read, written, or generated artifact paths, including target-project `.sealos/*` outputs.
- **terminal state** — `success`, `stopped`, or `error`.
- **handoff** — target, input artifact, allowed action, failure return, and response owner.
- **redaction** — explicit checks proving credential-shaped values, kubeconfig contents, connection strings, Secret data, and full ConfigMap values stay out of traces.
- **runtime artifact** — the generated path or sanitized evidence that demonstrates the terminal state.

The fixture is deterministic and offline by default. Positive traces model current success evidence. Violating traces model current fail-closed, stop, or confirmation behavior. No real auth, environment, kubeconfig, connection, or provider value is stored.
